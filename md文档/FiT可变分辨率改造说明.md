## 1. 改造前（main）是什么样

| 环节     | 做法                                                                                                       |
| ------ | -------------------------------------------------------------------------------------------------------- |
| 训练尺寸   | **固定 128×384（1:3）**，来自 `data.train_size`                                                                 |
| 分桶     | 静态 5 个桶 `DEFAULT_BUCKETS = [(64,1024),(96,512),(128,512),(128,384),(256,256)]`；`pick_bucket` 按"填充面积最小"选桶 |
| 数据过滤   | **`train_size` 之外的图全部丢弃**（`data/dataset.py`：只保留分类到该桶的图）                                                  |
| 内容图预处理 | `resize_and_pad_to_bucket`：contain 等比缩放 + 白色居中对称填充到 128×384                                              |
| DiT 输入 | latent 固定 `16×48` → patch=2 → grid 固定 `8×24` = **192 tokens**                                            |
| 位置编码   | 2D RoPE 已存在，但 grid 恒定，实际等价于固定尺寸                                                                          |
| 推理     | 固定输出 128×384，与输入原图比例无关                                                                                   |

## 2. 为什么要改（四个动机）

### 2.1 固定尺寸会毁掉长宽比失衡的样本 —— 本质是「字高」问题

真实公式图从 1:1 一路到 **1:10+**。把它们 contain 塞进 1:3 的桶：

```
样例 1000×100（1:10）：
  scale = min(128/100, 384/1000) = 0.384
  → 缩放后高度只有 38px，两侧被大量白边包围
```

- **字高从 ~128px 被砍到 38px**（约 1/3）。公式的笔画本来就只有 1~3px，  
  压到 38px 高之后大量笔画变成亚像素级，VAE encode 出来的 `z_p` 基本是噪声，  
  **内容条件直接失效**。
- 宽边方向还浪费了大量 token 在纯白背景上。

### 2.2 固定桶 = 白白丢数据

`main` 里 `train_size` 是**单个**尺寸，只有被分到 128×384 桶的图参与训练，  
其余长宽比的图**全部被过滤掉**（`No print images classified to train_size` 那条断言就是这么来的）。  
这是纯粹的数据浪费。

### 2.3 FiT 的核心论点：预处理收益 >> 位置编码技巧

FiT 论文消融（DiT-B/2 @400K，1:2 分辨率，FID↓）：

```
DiT-B 固定分辨率基线   91.32
  仅换「灵活训练」      50.51     ← 光改数据预处理就吃掉了绝大部分收益
  + SwiGLU            48.66
  + 2D RoPE           43.96     ← 架构 trick 是次要的
```

**这是本次改造的核心赌注**：把力气花在数据预处理上，而不是堆架构技巧。

### 2.4 推理端也需要可变分辨率

改造前输出恒为 128×384，与输入原图的比例无关 —— 用户拿到的图比例是错的。  
改造后按各自宽高比生成，并可用 `--restore_size` 还原到原始像素尺寸。

## 3. FiT 做了什么（三条核心）

> 一句话：**把图像看成一串长度可变的 token**，训练时按「token 预算」而非「固定画布」组织数据。

1. **按面积预算等比缩放**（保留宽高比，默认只缩不放），使 `grid_h × grid_w ≤ max_tokens`。
2. **按宽高比自动分箱**：同 batch 用同一个 canvas，空白 token 用 mask 屏蔽  
   （注意力里当 key 屏蔽掉 + loss 里不计数）。
3. **位置信息交给 2D RoPE**（相对位置、可外推），**绝对尺度用 grid 条件注入 AdaLN**  
   （`use_grid_cond`）。
4. 数据处理逻辑参考PATCH_RULES.md（来自新的VAE处理逻辑），注意图像预处理和patch打包逻辑要一致，这样才能保证整个模型自洽（VAE和FiT）
